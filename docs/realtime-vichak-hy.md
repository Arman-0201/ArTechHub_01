## Ինչպես է սա աշխատում (2 նախադասությամբ)

Socket-ը **տվյալ չի կրում** — միայն ասում է «այս բաժինը փոխվեց»։ Հետո բրաուզերը նորից կարդում է սովորական API-ից, որտեղ իրավունքները արդեն ստուգվում են։ Դրա համար է անվտանգ նույն socket-ը տալ և՛ անանուն այցելուին, և՛ ադմինին։

Երեք լսարան կա, և դրանք գումարվում են՝

| Լսարան | Ով | Ինչ է ստանում |
|---|---|---|
| `public` | բոլորը, նույնիսկ չգրանցվածները | միայն բաժնի անուն — ոչ id, ոչ անուն |
| `learner` | մուտք գործած օգտատեր | **միայն իր** տվյալները |
| `admin` | ադմին իրավունքով | ռեսուրս + գործողություն + ով արեց |

## ⚠️ Ինչը միտումնավոր չի աշխատում

Սրանք սխալ չեն։ Ամեն մեկը գիտակցված որոշում է։

### 1. `POST /content/pdf/preview`
Ոչինչ չի գրում բազայում — պարզապես կարդում է PDF-ը և վերադարձնում։ Եթե սա էլ event ուղարկեր, audit log-ը կլցվեր ոչ-փոփոխություններով, և էկրանները կթարմացվեին առանց պատճառի։

### 2. Մեկ սարքի session-ի չեղարկում
Երբ ջնջում ես ուրիշ սարքի session-ը, այդ սարքի socket-ը **միանգամից չի փակվում**։

Պատճառը՝ access token-ի մեջ session-ի id չկա (միայն `sub` և `ver`), ուրեմն hub-ը չի կարող տարբերել նույն օգտատիրոջ երկու socket-ը։ Եթե փակեինք, կփակվեր նաև **քո** նոութբուքի socket-ը։

Ընդ որում այդ սարքը HTTP-ով էլ դեռ մուտք ունի մինչև token-ի ժամկետը լրանա — ուրեմն սա socket-ի բաց չէ, այլ նույն վարքն է։ Ճիշտ լուծելու համար պետք է session id դնել token-ի մեջ։

### 3. Որոնում, զամբյուղի սինխրոն, վիդեոյի դիրք
Սրանց socket պետք չէ։ Որոնումը արդեն debounce-ով է, զամբյուղը՝ localStorage-ում, իսկ վիդեոյի դիրքը timer-ով չի ուղարկվում։

## 🔴 Ինչը դեռ մնում է անելու

| Ինչ | Ինչու է պետք |
|---|---|
| **Redis pub/sub** | Հիմա socket-ների ցուցակը մեկ պրոցեսի մեջ է։ Եթե երկրորդ API server ավելացնես, A-ի փոփոխությունը B-ի օգտատիրոջը չի հասնի։ Հիմա 1 server է, ուրեմն դեռ խնդիր չէ — բայց **անպայման պետք է անել երկրորդ server-ից առաջ**։ |
| **Job progress** | PDF ներմուծելիս և մեծ ֆայլ վերբեռնելիս միայն spinner է երևում — ոչ տոկոս, ոչ էջերի քանակ։ |
| **409 conflict** | Երկու ադմին նույն դասընթացը խմբագրելիս լուռ վերագրում են իրար։ Socket պետք չէ — պարզապես `updatedAt` ստուգում։ |
| **Presence** | «Դանան հիմա խմբագրում է այս էջը»։ Սա պահանջում է, որ բրաուզերը **ուղարկի** սերվերին, իսկ hub-ը հատուկ կառուցված է որպես միակողմանի ալիք։ Ճարտարապետական որոշում է, ոչ թե պարզ ֆիչր։ |

## Ինչպես ստուգել որ աշխատում է

1. Բացիր ադմին պանելը **երկու տարբեր բրաուզերում** (կամ մեկը՝ ինկոգնիտո)
2. Առաջինում փոխիր menu կետի տեսանելիությունը
3. Երկրորդը պիտի ինքնուրույն թարմանա **~2 վայրկյանում**

Հանրային կայքի համար՝ բացիր գլխավոր էջը սովորական բրաուզերում (առանց մուտք գործելու), հետո ադմինից փոխիր նավիգացիան։ Էջը կթարմանա **3–10 վայրկյանում**։

> Ուշացումը միտումնավոր է․ ուսանողի համար 0.4 վրկ (ինքն է սպասում), ադմինի համար 2 վրկ, այցելուի համար 3–10 վրկ պատահական ցրումով։ Առանց այդ ցրման մեկ հրապարակումը կստիպեր **բոլոր** բաց էջերին միաժամանակ վերարտադրվել սերվերի վրա։
